controls · components/base.css

Not a component — the base layer. Every button, input and focus ring in the kit is one of these, which is the whole reason a dialog footer, a menu item and a page toolbar cannot drift apart. Two ways in: the .vui-btn class anywhere on the page (below), or a bare <button> inside any vui component — see the dialog's “form” demo, whose buttons carry no classes at all.

The five filled variants are the design-tokens semantic roles, each with its own hover / active / foreground tokens — so the theme picker above switches all of them at once. A variant does not paint: it re-declares --vui-control-* on itself, the same mechanism a container uses, which is why it wins over the surface it sits on (try one in a dialog footer).

The inputs above carry no classes either: .vui-field is a vui- element, so the container hook reaches them. Tab through the row to see the one focus ring.

The checkbox, radio and range are the UA's own glyphs, tinted with one accent-color — the kit draws nothing. The switch is the sixth control, keyed on role="switch": the platform gives the semantics, the Space key and the form value, and CSS draws the track.

chrome · components/base.css

Also the base layer, also not components — and not controls either: nothing here hovers, focuses or presses, so none of it reads the control channel. A badge in a dialog panel stays the color it was told to be while every button around it lifts. They are here for the reason the controls are (markup a consumer writes, which a factory can never reach) and they stop where that argument stops.

a reset on the page · Bootstrap Reboot

Many vanilla prototypes start from Bootstrap Reboot plus the design-tokens reboot bridge. The kit is happy with that — on one condition. Flip the reboot picker up top and watch this row.

off — the kit alone. layer(reset) — Reboot imported into the reset layer this page declares before anything else (@layer reset, vui.base, vui.components); it resets the page and the kit still wins where they overlap. unlayered ⚠ — the same file loaded plainly: unlayered CSS beats layered CSS at any specificity, so Reboot's button {border-radius:0} and line-height:inherit defeat vui.base. Square buttons, and controls that no longer share a height with the select next to them.

a <summary> as a button

.vui-btn works on <button>, <a> and <summary> because it starts with all: unset. Unlayered Reboot's summary {display:list-item} undoes that — the marker and the full-width box come back.

The token side is friendlier: the files in gallery/themes/ are generated through the bridge, so they set --bs-* from the very same tokens as --vui-color-*, on :root and :root.dark alike. Two vocabularies, no collision — Reboot follows the theme picker and the dark toggle instead of painting Bootstrap's own white page. One ordering catch, and only while it is unlayered: reboot.css redeclares every --bs-* on :root itself, so it has to come before the theme or it overwrites the bridge (this page loads it first, as Reboot pages normally do). In a layer that stops mattering — the theme's unlayered custom properties win from anywhere.

dialog

Native <dialog>: top layer, backdrop, focus trap, Esc, focus restore. Close with ✕, Esc, the backdrop, or a footer button — every route ends in one vui:close event with a returnValue.

A drawer and a sheet are this component with a margin: placement pins the box to an edge and slides it in from there, and the top layer, the focus trap, Esc and focus restore are the ones already in the box. start / end are logical, so they follow the document direction.

tabs

				

					The first primitive the platform has no element for, so this
					one is the wiring: it pairs each tab with its panel
					(ids, aria-controls,
					aria-labelledby), moves the roving
					tabindex, and switches the panels. Two platform
					pieces still carry it. The tab is a
					<button role="tab"> — Enter and Space are
					its own, and the base layer paints it by that role, so the
					tabs here have no class at all. And an
					inactive panel is hidden="until-found": press
					⌘F / Ctrl+F and search for
					armadillo — it is only in the third tab, and
					the browser will open it for you.
				

				


				

					activation: "manual" — the arrows move focus,
					Enter or Space selects. For panels expensive enough that
					arrowing past them should not load them. (Focus a tab and
					try ← →.)
				

				


				

					orientation: "vertical" — the same component
					turned on its side: ↑ ↓ instead of ← →, the rail down the
					inline edge, and the indicator with it.
				

				


				

					More tabs than fit: the strip scrolls rather than wraps, so
					the rail stays one line — which is also why a tab draws its
					focus ring inside. (Tab into it and hold →.)
				

				


				

					
					
					
				

				

			


			
			

				
toast

				

					The first primitive that is a region rather than a
					widget: one call builds the rail, and every
					show() puts a message in it. It lives in the
					top layer (popover="manual") and
					re-enters it on every toast, so a message is never buried by a
					modal dialog's backdrop or by a page's z-index —
					try from inside a dialog. Hover a toast, or tab into
					one, and every clock holds — the countdown bars with them.
					Fire the same message twice and it gets a ×2
					badge instead of a second copy.
