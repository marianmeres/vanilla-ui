Reusable UI primitives on top of @marianmeres/vanilla, shipped as single-file .html components
(a <template>, a CSS @scope'd <style>, and the factory in an inline module script) loaded at
runtime with loadComponent — no build step, just serve. Every component root carries data-scope
so components nest without ref/action collisions; events go out as "vui:*" CustomEvents plus
callback props. Under the components sits one base layer (components/base.css, installed by
loadStyles): it reads the @marianmeres/design-tokens variables (prefix "vui-") once into a
vocabulary named token-minus-"color-" (--vui-surface-foreground) with system-color fallbacks,
adds structural tokens in stuic's tiers (radius element/button/container, shadow
resting/overlay/dialog, border-width, transition), and defines the control primitives — .vui-btn
with the five design-tokens semantic roles (primary, accent, destructive, warning, success,
each with hover/active/foreground) plus --ghost and --icon, .vui-input, .vui-field, .vui-row,
the focus ring — which also apply to bare <button> and <input> markup inside any component, so
slot content looks right with no classes. Buttons are styles, not components (button() builds
one as a plain element). Everything is in the vui.base / vui.components cascade layers, so
unlayered consumer CSS overrides it for free. Containers AND variants both work by re-declaring
the --vui-control-* channel (colors and sizes) on themselves, so a new role is five custom
properties and no new rule; the channel's defaults are var() fallbacks at the usage sites, never
:root declarations, so they resolve at the control. The
typed index (src/mod.ts) re-exports vanilla, resolves URLs from its own location, and exposes
loadAll()/load<Name>()/loadStyles(). Primitives so far: dialog on the native <dialog>; popover on
the native Popover API (popover="auto": top layer, light dismiss, nesting; a <button> anchor is
the native invoker), placed by CSS Anchor Positioning with position-try flips and by a small JS
measure/flip/clamp where a browser lacks it, and with role "menu" a menu (focus on open,
arrow/Home/End keys, Tab closes, vui:select with the item's value) whose items base.css paints by
their role alone (.vui-menu, .vui-menuitem, --destructive); and disclosure on the native
<details>/<summary> — a box, an isOpen observable and vui:open/vui:close over a platform that
already has the toggle, the keyboard, aria-expanded and find-in-page, with `name` giving a
natively exclusive accordion (no group component, no registry) and ::details-content the height
animation. The <summary> row is a base control too, keyed on the element (.vui-summary outside a
component), so a plain <details> in any slot comes out the same. Then tabs, the first primitive
with no platform element behind it: it takes the tabs as an array (a tab is a PAIR —
a label and a panel — and tying them together with ids and aria is the whole job; the array is
read once, nothing is diffed), writes the role="tablist" strip, the roving tabindex and the
arrow/Home/End keys (selection follows focus unless activation:"manual"), and turns on its side
with orientation:"vertical". Its tabs are <button role="tab"> with NO class — base.css paints
them by that role (.vui-tab / .vui-tablist outside a component) — and an inactive panel is
hidden="until-found", so find-in-page reveals it, fires beforematch, and the component selects
that tab.
Newest is toast, the first primitive that is a REGION rather than a widget: createToast()
builds a rail and every show(message, opts) puts one message in it (append and remove only, so
no diffing and no keys). The rail is popover="manual" — the top layer and nothing else —
RE-ENTERED on every show(), since the layer is ordered by entry and a modal <dialog> opened
after it would otherwise cover it (a modal still makes everything outside it inert, so a toast
over one is visible but not clickable). Six positions (top/bottom × start/center/end, block
axis as the flex direction so a new toast never moves the ones on screen), ttl with a countdown
bar, max capacity dropping the oldest, and an id — defaulting to the message text — that turns
a repeat into a ×N badge plus a restarted clock. The clock is a setTimeout and the bar only
draws it (a page's reduced-motion reset must not decide when a toast leaves); hover or focus in
the region sets data-paused and holds both. Entry via @starting-style, exit via a transition
plus a net read off the box. A variant TINTS the surface and its border (12% and 35% of the
role; full strength on the icon and the bar) instead of filling it, so the toast keeps ONE
control context — the dialog panel's — and its ✕ is the same base-layer ghost icon button.
